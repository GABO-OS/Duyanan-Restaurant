1. PURPOSE
================================================================================

  The purpose of this Test Summary Report is to summarize the results of manual 
  testing conducted on the Order Tracking & Fulfillment Dashboard (Admin Panel 
  - Orders Tab) of the Duyanan Restaurant Online Ordering System.

  The report provides stakeholders with an overview of the testing activities, 
  defects identified, test coverage, and recommendations regarding the release 
  readiness of the application.


================================================================================
2. SCOPE OF TESTING
================================================================================

  The following functionalities were included in this testing cycle:

  * View Incoming Orders Dashboard
    - Admin / Kitchen staff access to the active orders grid and stats.
    - Real-time loading of order records with complete column details.
    - Chronological sorting of incoming orders from newest to oldest.
    - Graceful empty state UI rendering and zeroed stats when database is empty.

  * Update Order Fulfillment Status
    - Order status updates via action dropdown (Pending, Preparing, Completed).
    - API validation to reject updates for non-existent order IDs.
    - Pricing, items, and location-based delivery fee integrity preservation.

  * Order Cancellation & Reason Validation
    - Order status cancellation flow triggered from the Action dropdown.
    - SweetAlert2 modal enforcement requiring a mandatory cancellation reason.
    - Input validation blocking empty and whitespace-only reasons.
    - Modal dismissal and cancellation revert logic.

  Out of Scope:
  The following modules were not included in this testing cycle:
  - User Authentication & Authorization Module (Login, Role Permissions)
  - Customer Ordering Frontend (Menu selection, Checkout flow, Custom tracking)
  - Sales Analytics & Forecasting Dashboard (Sales reports, popular items)
  - Catalog & Menu Item Management (Add/Edit/Delete menu items)

7. DEFECT ANALYSIS
================================================================================

  Critical Defects:
  None

  Medium Defects:

  * BUG-101
    The frontend dashboard crashes when the status update API returns a 404 error
    response.

    - Description:
      When a PUT status update is sent for a non-existent order (e.g. ID 999999),
      the Spring Boot API returns a text "404 Not Found" payload. The frontend
      is coded to read all status responses using res.json(). This mismatch
      causes an uncaught SyntaxError in the browser, crashing the execution path.
    - Impact:
      Dashboard locks up on updates to invalid orders; the SweetAlert2 error modal
      fails to appear; the action dropdown displays the invalid state to users.
    - Recommendation:
      Implement checks on Content-Type and HTTP response status before parsing
      JSON. Modify backend API controller responses to return standardized JSON
      error objects instead of plain-text payloads.

11. LESSONS LEARNED
================================================================================

  - Primary fulfillment dashboard flows and cancellation validations function
    correctly.
  - Frontend fetch mechanisms should be built defensively against non-JSON API
    errors.
  - Establish API payload contracts between backend and frontend developers
    early in the development cycle.
  - Implement automated E2E tests to speed up routine verification checks.


================================================================================
12. RECOMMENDATIONS
================================================================================

  1. Fix BUG-101 (defensively catch parsing issues on frontend).
  2. Configure backend to return JSON error responses rather than text payloads.
  3. Implement dropdown status rollback logic on AdminPanel status errors.
  4. Perform a regression test run after integrating the status fixes.
  5. Conduct final User Acceptance Testing (UAT) cycle prior to production release.
